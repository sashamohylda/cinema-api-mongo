# cinema-api-mongo

Серверна частина кінотеатру на NestJS: фільми, зали, сеанси та бронювання місць.
Дані зберігаються в MongoDB через Mongoose.

## 1. Встановлення залежностей

```bash
npm install
```

## 2. Змінні середовища

Створіть у корені файл `.env` (приклад — `.env.example`):

```env
PORT=3000
MONGO_URI=mongodb://localhost:27017/cinema
```

| Змінна      | Опис                        | Приклад                              |
| ----------- | --------------------------- | ------------------------------------ |
| `PORT`      | Порт застосунку             | `3000`                               |
| `MONGO_URI` | Рядок підключення до MongoDB | `mongodb://localhost:27017/cinema`   |

Без `MONGO_URI` застосунок не стартує (конфігурація валідується).

## 3. Підняти базу даних (Docker Compose)

```bash
docker compose up -d
```

## 4. Запуск у режимі розробки

```bash
npm run start:dev
```

Застосунок: `http://localhost:3000`, Swagger: `http://localhost:3000/docs`.

## 5. Засіяти базу тестовими даними

```bash
npm run seed
```

Додає 2 фільми, 2 зали, 4 сеанси в різні дати та 1 бронювання.
Повторний запуск не створює дублікатів.

## Чому місця й бронювання зберігаються всередині документа сеансу

Місця (`seats`) та бронювання (`bookings`) вкладені в документ сеансу, а не винесені
в окремі колекції. Причина — у способі, яким MongoDB забезпечує неподільність.

Оновлення **одного** документа в MongoDB атомарне саме по собі. Зміна кількох документів
однією неподільною операцією вимагала б транзакції, а транзакція — replica set.

Бронювання складається з двох дій: позначити місця зайнятими й зберегти сам запис.
Оскільки і місця, і бронювання лежать усередині одного документа сеансу, обидві дії
виконуються **одним** `updateOne`. Умова оновлення (`$elemMatch` з `bookingId: null`)
вимагає, щоб усі потрібні місця були вільні; якщо хоча б одне зайняте — документ не
змінюється й сервіс повертає `409`. Транзакція не потрібна.

Така модель коректна, бо кількість вкладених даних обмежена: місць у залі кілька сотень,
бронювань на сеанс не більше, ніж місць, тому документ не росте безмежно.

## Перевірка маршрутів

Файл `requests.http` у корені містить запити до всіх маршрутів у порядку створення
(фільм → зал → сеанс → бронювання) та запит на кожну помилку. Ідентифікатори
підставляються зі змінних відповідей.
